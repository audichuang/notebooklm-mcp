# Retracted attempts are tombstones; replacement is the only audited path

QA rejection of a completed episode goes through `podcast_attempt_retract` — a purely local, no-RPC supersede that voids the output attempt and pops the episode-level output evidence so a replacement can legally generate. Hand-editing `series_manifest.json` is not an alternative: it bypasses artifact-claim uniqueness, the dispatch baseline and every finalize checkpoint (EP35 shipped a hand-written attempt whose five timestamps shared one microsecond and whose `artifact_ids_before` listed its own artifact id). Four invariants hold this together, each locked by tests.

**Evidence is popped, not nulled.** `_promote_attempt_output` writes `published_at` with `setdefault`, so a lingering `None` would stop the replacement from recording its real production time — `publish_series` would not fail, it would silently emit a fabricated date (`_fallback_pub_date`), caught only downstream by `podcast-lab/scripts/check_episode.py`.

**A retracted attempt is a tombstone.** Three layers default-deny it: `_attempt_record` (reconcile / adopt / promote / supersede all refuse; only retract itself passes `allow_retracted=True`), `audio_finalize._record` (the single entry point for every finalize checkpoint read/write), and `ManifestStore._validate` (a write whose pointer references a voided attempt fails outright). An in-flight finalizer that started before the retract therefore cannot resurrect the rejected cut.

**Deleting the stale feedback source is a precondition on both paths**, not a documentation reminder: `pending_source_cleanup` + `_assert_source_cleanup_done` gate generation *and* resume, because finalize verifies by `source_id` and does not reject duplicate titles — a missed delete silently leaves two identically named media sources polluting later context. The obligation is read from the attempt's finalize checkpoint rather than the episode-level projection (that projection is a legacy-compatibility field: it can be missing, and `adopt` can rewrite it). It must cover all three entry points (`_run_episode` / `podcast_episode_resume` / `podcast_series`'s per-episode preamble), must verify notebook identity before querying (querying some other empty notebook would mark the obligation discharged), and must clear only the entries actually observed absent in that pass, since new obligations can accrue during the await.

**A replacement may not change the title**, enforced at both attempt-creation entry points (`_create_audio_attempt` and `_ensure_resume_attempt`), and its local mp3 always lands under `attempts/<attempt_id>/` — keyed off `has_durable_output_evidence` recognising `retracted_attempt_ids` rather than on whether a `cover_path` happens to exist — so the rejected cut's evidence is never overwritten. Relatedly, `_ensure_resume_attempt` no longer accepts "a different artifact" once durable output exists; that older behaviour made resume an unaudited replacement back door, since promotion had no ownership check and swapped the output pointer the moment finalize succeeded. Two existing tests had encoded that behaviour as spec and were rewritten to exercise the legitimate retract path. The gate must exist on **both** creation branches — `_ensure_resume_attempt` has a claimed branch (the artifact is already claimed by some attempt) as well as a new-attempt branch, and the claimed branch was the third entry point and the only read/write that bypassed the `_attempt_record` tombstone.

Retract is idempotent: a repeat call clears only its own residue, and once a replacement has taken over the output pointer it is a full no-op. An active/output divergence — produced by an older version or by hand-editing — is resolved by retracting the unauthorised candidate.
