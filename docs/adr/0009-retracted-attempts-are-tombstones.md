# Retracted attempts are tombstones; replacement is the only audited path

QA rejection of a completed episode goes through `podcast_attempt_retract` — a purely local, no-RPC supersede that voids the output attempt and pops the episode-level output evidence so a replacement can legally generate. Hand-editing `series_manifest.json` is not an alternative: it bypasses artifact-claim uniqueness, the dispatch baseline and every finalize checkpoint (EP35 shipped a hand-written attempt whose five timestamps shared one microsecond and whose `artifact_ids_before` listed its own artifact id). Four invariants hold this together, each locked by tests.

**Evidence is popped, not nulled.** `_promote_attempt_output` writes `published_at` with `setdefault`, so a lingering `None` would stop the replacement from recording its real production time — `publish_series` would not fail, it would silently emit a fabricated date (`_fallback_pub_date`), caught only downstream by `podcast-lab/scripts/check_episode.py`.

**A retracted attempt is a tombstone.** Three layers default-deny it: `_attempt_record` (reconcile / adopt / promote / supersede all refuse; only retract itself passes `allow_retracted=True`), `audio_finalize._record` (the single entry point for every finalize checkpoint read/write), and `ManifestStore._validate` (a write whose pointer references a voided attempt fails outright). An in-flight finalizer that started before the retract therefore cannot resurrect the rejected cut.

**Deleting the stale feedback source is a precondition on both paths**, not a documentation reminder: `pending_source_cleanup` + `_assert_source_cleanup_done` gate generation *and* resume, because finalize verifies by `source_id` and does not reject duplicate titles — a missed delete silently leaves two identically named media sources polluting later context. The obligation is read from the attempt's finalize checkpoint rather than the episode-level projection (that projection is a legacy-compatibility field: it can be missing, and `adopt` can rewrite it). It must cover all three entry points (`_run_episode` / `podcast_episode_resume` / `podcast_series`'s per-episode preamble), must verify notebook identity before querying (querying some other empty notebook would mark the obligation discharged), and must clear only the entries actually observed absent in that pass, since new obligations can accrue during the await.

**A replacement may not change the title**, enforced at both attempt-creation entry points (`_create_audio_attempt` and `_ensure_resume_attempt`), and its local mp3 always lands under `attempts/<attempt_id>/` — keyed off `has_durable_output_evidence` recognising `retracted_attempt_ids` rather than on whether a `cover_path` happens to exist — so the rejected cut's evidence is never overwritten. Relatedly, `_ensure_resume_attempt` no longer accepts "a different artifact" once durable output exists; that older behaviour made resume an unaudited replacement back door, since promotion had no ownership check and swapped the output pointer the moment finalize succeeded. Two existing tests had encoded that behaviour as spec and were rewritten to exercise the legitimate retract path. The gate must exist on **both** creation branches — `_ensure_resume_attempt` has a claimed branch (the artifact is already claimed by some attempt) as well as a new-attempt branch, and the claimed branch was the third entry point and the only read/write that bypassed the `_attempt_record` tombstone.

Retract is idempotent: a repeat call clears only its own residue, and once a replacement has taken over the output pointer it is a full no-op. An active/output divergence — produced by an older version or by hand-editing — is resolved by retracting the unauthorised candidate.

**Amended in v0.9.0 — "unauthorised candidate" now covers two more shapes, because the original one left a real state with no legal exit.** The trigger was an episode whose attempt had been *accepted by the server* while the brief fed into it was wrong: letting it finish was pointless, yet every door was shut. Retract refused it (not the durable output), a corrected brief hit "already has durable active attempt", an identical re-call was refused by `_is_resendable_same_request` (it had already dispatched), `supersedes_attempt_id` hit "is not terminal", and adopt/reconcile both require a finished finalize. The only route left was to let the wrong cut run to completion, promote it, then retract it — paying for a download, a feedback-source upload, a promotion and a `source_delete` to undo something already known to be wrong.

The first new shape is mechanical: an episode carrying **legacy episode-level hard evidence** (`artifact_id`/`mp3_path` written directly on the episode before v0.5.0) but no `output_attempt_id`. Here the field-popping branch must also run, or clearing the retract door alone just moves the wall — the next generation is refused by `has_hard_output_evidence` instead.

The second is **`abandon_in_flight=True`**, and it is deliberately a caller-supplied flag rather than a state test. "The input to this attempt is wrong" is knowledge the manifest does not contain and cannot derive: field for field, that attempt is indistinguishable from a healthy first dispatch still waiting on `wait_for_completion`, which belongs to reconcile/resume. So the caller declares it, the reason is recorded as with any retract, and the default keeps the old refusal — a widened *state* rule would have quietly annexed reconcile's territory. The flag only ever admits the attempt sitting in `active_attempt_id`; it is not a general manifest-rewrite key, and every other invariant above (tombstone default-deny across the three layers, popped-not-nulled evidence, the stale-source precondition on both generation paths, the unchanged title, `attempts/<attempt_id>/` for the replacement) is untouched.

It does **not** save quota — generation is already burning, and retract is purely local, so the remote artifact keeps running and is simply orphaned. `_claimed_artifact_ids` scans every attempt including retracted ones, so that orphan can never be mis-claimed by a later reconcile. What is saved is the wasted finalize round and the polluting feedback source it would have uploaded into every subsequent episode's context.

**Amended in v0.9.12 — an obligation the manifest cannot yet name is still recorded, never converted into a block.** The v0.9.11 tree closed retract entirely (flag included) while the feedback-source upload sat at `dispatching` with no `source_id` on the checkpoint, reasoning that a tombstone there would orphan a media source nobody remembers. The concern is real; the remedy inverted this ADR. That state is not a momentary commit-point window but a *durable* one: `claim_upload` persists `dispatching` before awaiting `add_file`, and the surrounding handler was `except Exception`, which does not catch `CancelledError` — so a cancelled MCP request (or a killed process) leaves it there permanently, with the only exit, `_reconcile_source_upload`, reachable solely from `finalize_attempt`. Abandoning a known-wrong attempt therefore required finishing it first: download, feedback-source upload, promotion, *then* retract and `source_delete` — precisely the waste the v0.9.0 amendment exists to prevent, plus a hard deadlock whenever the notebook can no longer be listed.

So the flag passes, and the tombstone carries `source_cleanup_unresolved`. Three properties make that safe. **The obligation records a state, not a copy**: `source_ids_before` / `expected_title` / `dispatched_at` stay on the attempt's finalize checkpoint (a tombstone does not delete the attempt), because a second copy is a second thing to drift. **The candidate rule has exactly one implementation** — `unresolved_upload_candidates()`, shared by finalize reconciliation and by cleanup — since baseline/title/kind/dispatch-window/already-claimed is five conditions, and any of them missing from a second copy either adopts another episode's recording as this orphan or misses a real one. **Discovery is fail-closed on time, not on emptiness**: `_assert_source_cleanup_done` queues whatever it finds into `pending_source_cleanup` (persisting *before* raising, so a half-finished delete loop does not lose the rest) and only discharges the obligation once the dispatch window has closed *and* the notebook lists zero candidates under a confirmed canonical identity. Zero candidates with the window still open, a window closed but identity unconfirmed, and a failed `sources.list` are all refusals. Scope covers all three unresolved statuses (`dispatching` / `acceptance_unknown` / `reconciliation_ambiguous`), because the consequence — a media source in the notebook that the manifest cannot name — is identical for all three.

The cost is explicit: after abandoning such an attempt, regeneration is refused for up to `UPLOAD_DISPATCH_WINDOW` (12 minutes) even once the discovered orphan is deleted, since a late upload can still surface while the window is open. `safe_next_action` is `None` there rather than the regeneration entry — promising a door the generation gate will slam is the failure mode ADR-0010's transparency clause and the `_attempt_capabilities` red line both exist to prevent. Callers who want that source's identity preserved should resume instead of retracting; resume reconciles it and the obligation disappears.
