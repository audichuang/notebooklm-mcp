# Research yields candidates; the host decides what enters a notebook

`research_start` / `research_wait` / `research_import` expose NotebookLM's built-in Web and Deep Research as three separate capabilities, never as one discover-and-import call. `research_wait` returns candidate sources plus the report and imports nothing; `research_import` imports only the URLs the host names, and raises on a URL that is not in the candidate set rather than silently importing fewer. The `cited` flag on a candidate is a fact — whether that URL appears in the report's citations, computed locally with `notebooklm.research.extract_report_urls` — not a selection MCP made on the host's behalf; cited-only filtering, provenance, recency, version and duplicate judgement stay in the Audicast skill (ADR-0007). Splitting start from wait mirrors the attempt/resume discipline of ADR-0001: a pollable `task_id` lands before the wait, so a client-side timeout during a deep run (tens of minutes) is resumed by re-calling `research_wait` instead of starting — and paying for — a second research task. The MCP field stays `task_id` for compatibility, but its value is selected by mode rather than guessed: fast uses the SDK `task_id`, while deep uses `report_id` because its SDK `task_id` is an unpollable session ID.

Two consequences worth stating. `research.start` sends only the query string and the notebook id: sources already in the notebook do not inform the search, so seeds reach NotebookLM only as terms written into the query. And because import targets the notebook the research ran in, research belongs in a throwaway scratch notebook, with approved sources added to the episode notebook via `source_add_url` — otherwise every rejected candidate pollutes the source set the episode's audio, slides and report are generated from. This capability was already scoped in the 2026-06-07 redesign design doc (`research_start`, `research_wait_import`) and was dropped during implementation with no decision recorded, which is why it stayed invisible for 38 episodes: dropping planned scope needs an ADR too.
