## 5. 改完怎麼驗

依本 repo AGENTS.md 的驗收分層,這屬於**層 2(改到呼叫端讀得到的 skill 文字)**:

1. `uv run python scripts/check_skill_sync.py` —— 確認沒動到工具名與 `REQUIRED_CONTRACT_TERMS`
   (本次只改標記與措辭,理論上不會碰到,但它是 CI 硬檢查)。
2. `scripts/eval_harness/`(`claude -p` + dry-run stub,零帳號、零配額):至少跑會碰到
   **被降級標記**的情境,確認路由沒變差 —— 特別是 105(來源 >= 10 筆)、170(逾時)、
   308(非 Audicast 封面)、26(`notebook_list` 找不到)。這幾處拿掉標記後,模型仍要走對的路。
3. audi-skill 的 `AGENTS.md` 規定「改既有技能的流程語意」要 3 次舊版 + 3 次候選;純措辭與標記
   可以只跑 `quick_validate`。**標記降級介於兩者之間**:保守做法是對上面第 2 點那幾個情境跑 3+3。
4. 在 audi-skill 內:`python3 skillgenie/scripts/quick_validate.py notebooklm`(需要 PyYAML)。
5. commit、push 到 audi-skill 後,每台機器要 `aghub-cli -g source sync audichuang/audi-skill
   --skill notebooklm --update --yes` 才會拿到新版(私有 repo 需要 `GITHUB_TOKEN`)。
